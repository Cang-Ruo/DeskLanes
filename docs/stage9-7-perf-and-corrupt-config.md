## 2. B6 - 大量项目性能

### 2.1 启动耗时：新增 `tools/measure-startup.py`

思路：真实启动**发布后的自包含 exe**，用 `EnumWindows` 轮询"主窗口标题可见"作为终点，
而不是等进程退出——单文件应用启动后进程会一直活着，等退出会永远卡住。

- **冷启动**：先删掉 `%TEMP%\.net\DeskLanes\`（单文件解压缓存）再启动
- **热启动**：连跑 3 次取中位数
- 顺带断言 `logs/errors.log` 在启动过程中 **0 增长**
- 跑之前把 `settings.json` 的 `WindowMode` 强制为 `Full`（否则可能停在侧边栏/悬浮窗，主窗口不出现），
  结束时**原样还原**配置

实测（本机，自包含版）：

|---|---|---|
| 冷启动到主窗口可见 | < 3 s | **1.35 s** ✅ |

## 3. C10 - 配置损坏恢复：**查出一个真缺陷并修掉**

### 3.1 缺陷

给 C10 补"提示有没有真的上屏"这条断言时，冒烟直接挂了 4 条。根因：

```csharp
public async Task InitializeAsync()
{
    if (_workspace.LoadWarnings.Count > 0)
    {
        WarningText = "配置提示：\n" + ...;   // ① 写进去
    }

    await RefreshAsync();                     // ② 进来第一句就是 WarningText = null
}
```

`RefreshAsync()` 开头为了清掉上一轮的扫描警告，直接 `WarningText = null`——
**启动时的配置提示被紧随其后的首次扫描清掉了，用户什么都看不到**。
配置损坏时界面表现是"静默回退默认值"，而 C10 的判据明确要求"有用户能看懂的提示"。

这个问题靠读代码不容易发现（两处赋值相隔两个方法），是"把 C10 写成可执行断言"才逼出来的。

### 3.2 修法

配置警告与扫描警告**分开存**，不再共用一个字段：

- 新增 `_configWarningText`，只在 `InitializeAsync` 里写一次
- `WarningText` 的 getter 改成 `_warningText ?? _configWarningText`（扫描警告优先）
- `HasWarning` 随之联动
- 新增 `DismissWarnings()`：点"忽略"时**两类一起消**，否则关掉了还会再冒出来
- `DismissWarningCommand` 改走 `DismissWarnings()`

### 3.3 断言（冒烟第 21.3 节，7 条全过）

| 断言 | 目的 |
|---|---|
| `HasWarning` 为真 | 提示条可见 |
| 提示以「配置提示：」开头 | 是中文的，不是英文异常堆栈 |
| 提示里含「损坏」 | 说明了原因 |
| 提示里**不含** "Exception" | 不是异常类名/堆栈 |
| `backups/` 目录存在 | 损坏原件已备份 |
| 未弹错误对话框 | 只在窗口内提示，不用弹窗打断 |
| **首次刷新后提示仍在** | 本轮修的那条 |
| 点忽略后消失 | 用户能关掉 |

> 另一个踩坑：`dialogService` 是冒烟里共享的顶层实例，前面几节可能已经记录过
> "快捷键注册失败"之类的错误。断言"配置损坏不弹错误对话框"必须用**增量**
> （记录调用前的条数再比），不能直接判 `Count == 0`。
