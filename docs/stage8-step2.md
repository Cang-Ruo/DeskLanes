### 3.1 第 1 项：缺运行时的报错（虚拟机 05:27）

新脚本正确识别出报错对话框并截图（`vm-check-fail.png`）。用户截图里对话框内容：

- 标题：`DeskSpace.exe`
- 正文：**"You must install .NET Desktop Runtime to run this application."**
- 按钮：**"Download it now"**（附注 "You will need to run the downloaded installer"）

判定：**"启动失败要有明确提示"达标** —— 不是静默消失、不是十六进制错误码，
而是明确告诉用户缺什么，并且给了一个直达下载页的按钮。

两点要如实记录：

1. 虚拟机是**英文系统**（报告显示"专业版"，本机显示"家庭版 中文版"），所以框是英文。
   .NET 的宿主有本地化资源，中文系统下大概率显示中文，但**这一点没在中文系统上验证过**。
2. 即便在中文系统下显示中文，用户仍要自己在下载页挑版本（"桌面运行时 / Windows x64"）。
   要彻底解决，得做一个中文引导 launcher —— 属于新功能，**本阶段不做**，已列入
   `docs/project-overview-and-roadmap.md` 的 P3 候选。

顺带修掉 vm-check.ps1 的一个输出 bug：`Say '...' + $var + '...'` 这种不带括号的裸拼接，
在 PowerShell 5.1 下会被解析截断（同一段代码里带括号的拼接就正常），统一改成 `-f` 形式。

### 3.2 第 2 项：DPI 与窗口定位

| 机器 | DPI | 分辨率 | 版本 | 窗口 | 中心点 | 结论 |
|---|---|---|---|---|---|---|
| 虚拟机 | 96（100%） | 1920×1080 | 自包含 | 「DeskSpace」1100×720 @(370,136) | (920,496) 在屏内 | ✅ |
| 虚拟机 | 120（**125%**） | 1920×1080 | 自包含 | 「DeskSpace」1375×900 @(854,144) | (1542,594) 在屏内 | ✅ |
| 本机 | 120（125%） | 2560×1440 | 便携 | 「DeskSpace 快速启动」775×650 @(64,64) | (452,389) 在屏内 | ✅ |

两种 DPI 档位 × 两种分辨率 × 两种版本，窗口都在屏内，没有因缩放跑出屏幕。
125% 下窗口按物理像素放大到 1375×900（WPF 的 Per-Monitor DPI 感知在起作用）而非变形。

**限制**：150% / 200% 两档没测（虚拟机缩放可调但没继续测）。
考虑到 WPF Per-Monitor V2 是系统级行为、且已覆盖 100%/125% 两档 + 全屏/悬浮窗两种窗口类型，
风险可控，记录为已知限制而非阻塞项。
