### 3.1 第 1 项的实测（2026-10-25 05:07，虚拟机）

便携版放在 `C:\Users\Public\Documents\vm-package-portable\`，本机无运行时。

vm-check 报告第 4 节：

```
结果      : ✓ 进程仍在运行（15 秒后）
可见窗口  : 1 个
   「DeskSpace.exe」 位置=(674,374) 大小=556x222
```

**解读**：那个 556×222、标题为「DeskSpace.exe」的窗口就是 **.NET 缺运行时的系统报错对话框**
（应用自己的窗口标题是「DeskSpace」/「DeskSpace 快速启动」，绝不会带 .exe 后缀）。
进程没有退出是因为对话框在等用户点按钮 —— 也就是说：

> **"启动失败有明确提示"这条基本成立**：不是静默消失，而是弹了一个居中的对话框拦住，
> 用户必须做出反应才能继续。差一步：确认对话框里的**文案**能不能让人看懂该去装什么。

**同时暴露了 vm-check.ps1 的一个 bug（已修）**：脚本原来只认"进程退出=失败"，
把报错对话框误判成"启动成功"，因此没走到截图分支就 `Stop-Process` 把对话框关了
—— 这就是用户反馈"运行脚本不能自动截图"的原因。
修复后：可见窗口标题 == exe 文件名（如「DeskSpace.exe」）→ 判定为报错对话框 →
**先截图再关进程**，exit 2。本机自检确认正常启动分支不受影响。
