## 一、这一轮做了什么

### 1.1 悬浮窗八方向自由缩放

9.4 只有右下角一个手柄；现在**四条边 + 四个角**都能拖：

```
┌─ TL ──────── T ──────── TR ─┐
│                             │
│      ← 顶部 5~22 DIP 是拖动条 →
L      （窗口最上 5 DIP 拉高）  R
│                             │
│                             │
└─ BL ──────────────── BR(斜线)┘
```

* 左/右/下三边各 6 DIP 热区，四角 16×16；
* 顶部被「拉高（最上 5 DIP）」和「拖动（往下 17 DIP）」分掉 —— 分界线刻意拉开，
  否则一次点击会因像素舍入落在另一边（实测踩过：8 物理像素 = 6.4 DIP 正好骑在 6 DIP 分界上）；
* 所有热区仍全部落在 Border 的 14px Padding 内，透明、无新增可见元素；
* 左/上边缩放时窗口左上角跟着走，且顶到最小尺寸就停（不会"边框不动窗口却在长"）。

### 1.2 窗口按「所在显示器」自动收缩（窄屏适配的核心）

新增 `Core/Native/MonitorInterop.cs`（`MonitorFromWindow` / `GetMonitorInfo` /
`GetDpiForMonitor`）+ `App/Services/MonitorService.cs`，按**窗口所在那块屏**取工作区
（DIP），`FitIntoWorkArea` 只缩不放：

| 场景 | 之前 | 现在 |
|---|---|---|
| 悬浮窗拖到竖屏副屏（720 DIP 宽） | 780 DIP → 物理 1170，**溢出 90** | 自动收窄到 712 DIP → 物理 1068，进屏 |
| 主窗口在竖屏副屏最大化 | `MinWidth=900` 强制 1350 物理，**溢出 270** | `MinWidth=620`，实测 1102（= 1080 + WPF 最大化外扩 22） |

调用时机：悬浮窗在 `SourceInitialized`（显示前，避免闪烁）与每次拖/缩结束各收一次；
主窗口在 `BeginFullMode` 里对非最大化状态收一次。

**DPI 换算的关键取舍**：DPI 必须按**显示器句柄**（`GetDpiForMonitor`）取，不能用
`GetDpiForWindow` —— 窗口刚跨屏拖过去时，窗口自身的 DPI 要等 `WM_DPICHANGED`
处理完才更新，会拿到旧值导致"该收缩却不收缩"（实测踩过）。位置不做逐屏换算
（混合 DPI 下 WPF 的 `Left` 按主屏 DPI 换算，尺寸才按本屏 DPI，口径不一致），
收缩后交给既有的虚拟屏钳制处理位置。

### 1.3 主窗口的配套修复

* `MinWidth 900 → 620`、`MinHeight 520 → 420`：这是竖屏最大化的**前提** ——
  `MinWidth` 大于屏幕宽时，WPF 最大化也会被撑到 `MinWidth`，必然溢出；
* 窄态（`ActualWidth < 900`）自动折叠副标题，把宽度让给右侧 6 个按钮；
* **修了一个启动时序 bug**：窗口偏好原来在 `ContentRendered` 里恢复，晚于
  `BeginFullMode` 的最大化 —— 用户上次把主窗口留在副屏时，这次会先在主屏
  最大化、副屏偏好直接丢失。已移到 `SourceInitialized`（窗口定位之前）。
  顺带发现并防住：**已最大化时再设 `Left/Top` 会把窗口挪走**，偏好恢复现在
  会跳过最大化状态。

### 调试过程中踩的坑（勿重蹈）

1. **改完代码只 build 没 publish，端到端脚本跑的还是旧 exe** —— 第一轮"热区全部无效"
   的假象就是这么来的（旧 exe 根本没有八向热区）。脚本跑之前必须确认 publish 的 MD5。
2. 需要看热区实际覆盖位置时，临时把热区涂上半透明色 + 重新 build + 拍快照，
   比推理 Margin 快得多（本次涂色快照因为没 build 而作废，重新做才有效）。
3. 测试脚本轮次间会互相污染：Round E 把主窗口留在副屏并持久化，下一轮 Round A 的
   "主屏最大化"断言就挂了。每轮开始必须把主/悬浮窗位置与最大化标志全部重置。
4. 给 Round E 配置副屏坐标时，WPF 的 DIP 按主屏 DPI 换算：副屏物理 [-1080,0] 对应
   DIP [-864,0]，写 -1000 会在虚拟屏外、被可见性检查正确拒绝。

## 四、竖屏残留限制

* 主窗口在竖屏上是"最大化可用"，但**还原成普通窗口**时默认 1180 DIP 仍放不下
  （用户可手动缩小，`MinWidth=620` 允许；没有做"按屏自动选默认尺寸"）；
* 侧边栏展开宽约 200 DIP，720 宽竖屏放得下，但会遮挡桌面图标（原有行为，未改）；
* 混合 DPI 间拖动窗口时尺寸跳变（WPF 整窗按目标 DPI 重渲染，固有行为）。
