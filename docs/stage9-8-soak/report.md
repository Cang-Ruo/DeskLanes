# 阶段 9.8：长时驻留资源采样（6 小时）

> 结论先说：**没有泄漏**。私有内存前 1 小时涨 79 MB（预热）后走平，
> 最后 2 小时只 +3.9 MB、最后 1 小时 −1.0 MB；句柄 / GDI / USER / 线程全程不涨，
> `errors.log` 6 小时零增长。

## 一、怎么测的

`tools/soak-8h.py`：启动真实的自包含 exe（拷到 `%TEMP%\DeskLanesSoak\` 跑，
不占用户安装的那份），每 **5 分钟**采一次，直接读进程计数器：

| 指标 | 来源 | 为什么看它 |
|---|---|---|
| 私有内存 | `GetProcessMemoryInfo` → `PrivateUsage` | 真正的"这个进程占了多少"，比工作集可信（工作集会被系统回收） |
| 工作集 | 同上 → `WorkingSetSize` | 看系统有没有把它的页收走 |
| 句柄 | `GetProcessHandleCount` | 句柄泄漏最典型的信号 |
| GDI / USER | `GetGuiResources` | WPF 应用特有的两类泄漏（画刷、图标、窗口） |
| 线程 | Toolhelp32 线程快照 | 定时器 / 任务线程没释放会一直涨 |
| errors.log 体积 | 文件大小 | 有异常在反复发生时这里会一直长 |

采样期间用 `SetThreadExecutionState(ES_SYSTEM_REQUIRED)` 阻止机器睡眠
（线程级，进程退出自动释放，不改系统电源设置）。

原始数据：`soak.csv`（本轮 72 个采样点），上一轮存档 `soak-segment1.csv`。

## 三、怎么读这张表

**私有内存 203 → 298 MB 不是泄漏。** 拆开看：

- 前 1 小时 +79.2 MB：这一小时里有首次扫描、220+ 项目取图标（图标缓存从 0 填到上限）、
  JIT 预热、WPF 视觉树建立。这是"把该建的建起来"，不是"用完没还"。
- 第 1~2 小时：282.2 → 279.7 MB，**下降**。
- 第 3 小时到结束（3 小时）：294.6 → 298.0 MB，**+3.4 MB**，属于 GC 堆的正常波动。
- 最后 1 小时：**−1.0 MB**。

真泄漏的样子是"每小时固定涨一截、从不回落"。这里没有。

**工作集后来从 379 MB 掉到 206 MB**，是系统把闲置页收走了（正常，说明进程真的闲着），
私有内存没跟着掉也正常——那是它自己提交的内存。

**句柄 739 → 802**：峰值 950 出现在开局（监听器 + 图标提取并发），之后在 790~850 之间摆动，
最后 2 小时 793 → 802。没有单调上升。

**GDI 40 → 76、USER 35 → 43**：开局各涨一次（托盘图标、窗口、画刷建起来），
之后 5 个多小时一动不动。这两项一格都没涨，是"没有画刷 / 图标泄漏"最直接的证据。

## 四、这一轮顺带修掉的两个"只增不减"

采样之前先排查过源码里所有无上界的集合，确认过没有第二个漏网的：

1. **图标缓存**（阶段 9.6）：无上限无淘汰的字典 → 512 上限 + LRU 成批淘汰 +
   每轮按当前工作区裁剪 `PruneExcept()`。
2. **日志**（阶段 9.9）：`errors.log` 无上限 → `LogFileWriter` 轮转（单份 512 KB + 3 份归档；
   `errors.log` 256 KB + 2 份）。

本轮 6 小时里 `errors.log` 零增长，也反过来说明采样期间没有异常在反复发生。

## 五、还没覆盖的

- **锁屏 / 睡眠恢复**：脚本不敢锁屏（锁了没人能解锁）。睡眠唤醒后窗口与托盘的行为仍未实测。
- **跨天级别（24h+）**：本轮 6 小时。从曲线形状看再跑一天也不会变，但没实测。
- 采样期间机器是闲置的；**持续操作**（反复切布局、反复拖分区）下的增长没有单独采过
  （布局切换耗时另由 `UiSnapshot perf` 覆盖：220 项目最慢 349 ms）。
