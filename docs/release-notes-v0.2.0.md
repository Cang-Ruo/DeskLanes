# DeskLanes v0.2.0

**这一版只改界面，不加功能。** 之前做出来的效果是「一块深色软件窗口浮在桌面上」，
跟想要的「一层轻盈的玻璃面板」不是一回事。这一版把它改成后者。

## 改了什么

背景材质原来用错了：代码写的是 Mica 优先，而 Mica 在本机总能设置成功，
于是 Acrylic 分支永远走不到 —— 界面能吸收到壁纸的**颜色**，但看不到壁纸的**影像**。

两者不是同一种东西：

| | Mica | Desktop Acrylic |
|---|---|---|
| 官方定义 | 不透明材质，只把壁纸的**颜色**融进窗口背景 | 半透明磨砂玻璃，**显示并模糊**窗口后面的桌面内容 |
| 你能看到 | 一层随壁纸变色的底色 | 壁纸的图案被模糊后透上来 |

现在按 **Acrylic 优先 → 被拒降级 Mica → 再退不透明** 的顺序走，窗口永远可见。

其余改动：

- **原生标题栏与玻璃区割裂**：延伸玻璃框后标题栏仍是一块深色实心条。
  Acrylic 生效时改用 `DWMWA_COLOR_NONE`，让标题栏同样透出材质
- **悬浮窗与主窗口风格不一致**：悬浮窗原是分层窗口，用不了 DWM 材质，
  只能垫一块 90% 不透明的深底。改为 WindowChrome 非分层窗口后走真 Acrylic，
  拖动与八方向缩放的热区行为不变
- 玻璃 tint 全部调轻：窗口基底 35%→18%、导航 55%→35%、面板 30%→14%、卡片 45%→24%
- 顶部存在感降低：标题 19px 粗体 → 13px 中等字重，按钮收窄并加轻量符号，
  搜索框不再横贯整窗
- **底部移除区改为拖拽时才出现**（原为常驻红横条）

有意保留：**侧边栏**仍是深色底 —— 它是贴边窗口，DWM 圆角会把贴边那侧切成缺角，得不偿失。

## 一个被纠正的结论

之前代码注释里写着「本机实测 Acrylic 不渲染」。这个结论是错的，
错在取证方法：当时用视觉树快照（`RenderTargetBitmap`）判断材质，
而它抓的是 WPF 的视觉树，**本来就看不见 DWM 合成的材质和桌面壁纸**。

改用屏幕合成截图（GDI BitBlt）后重做 A/B 对照：

| 材质 | 窗口区域唯一颜色数 | 肉眼 |
|---|---|---|
| Acrylic | **5486** | 透出壁纸的模糊图案，有明暗层次 |
| Mica | 2549 | 均匀色块，没有纹理 |

取证过程与截图在 `docs/ui-acrylic-probe/`。

顺带记一条：**半透明 ≠ 磨砂**。中途试过「把分层窗口底色降到 75%」，
实测后面窗口的文字会清晰透进来干扰阅读 —— 分层窗口没有模糊能力，
这正是 DWM Acrylic 存在的意义。

## 升级

覆盖安装即可：把新的 `DeskLanes.exe` 换掉旧的，分类与布局都在
`C:\Users\<用户名>\AppData\Local\DeskLanes` 里，不会被清掉。
**无自动更新**（刻意不做静默自更新）。

## 已知限制（装之前建议看一眼）

完整清单在仓库的 [`docs/known-limitations.md`](known-limitations.md)，挑几条重要的：

- 没有数字签名；**无自动更新**
- **只支持 Windows 11**：玻璃材质走 DWM 系统背景，需要 22621+；Win10 未验证
- DPI 已验证 100% / 125% / 150% 与混合 DPI；**200%+ 与 1366×768 及以下未覆盖**
- 长时驻留实测过 6 小时（内存走平、句柄不涨），但**锁屏 / 睡眠唤醒后的行为未验证**，
  跨天（24h+）也没跑

桌面上的文件一个都不会被动：分类与分区只是记在 JSON 里的归属关系。
