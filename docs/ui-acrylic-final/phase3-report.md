# 阶段 3：亮 / 暗壁纸可读性验收

> 结论先放前面：**暗壁纸基本合格，接近纯白的壁纸不合格**（正文对比度 3.0~3.6，低于 WCAG 正文 4.5）。
> 已按"只给文字加极轻局部底"的方式做了最小修补；整体加深面板与统一加强投影都没有做。

---

## 一、测试条件

| 项 | 值 |
|---|---|
| 程序 | `publish/win-x64/DeskLanes.exe`（真实 exe） |
| 屏幕 | 2560×1440 @125%（DPI 120），单屏满屏 |
| 暗壁纸 | `wallpapers/dark.bmp`：深蓝黑底 + 三个高光斑（明暗变化明显） |
| 亮壁纸 | `wallpapers/light.bmp`：接近白（亮度 226~248）+ 极浅渐变（最坏情况） |
| 窗口状态 | 全部 `active=true`，`BACKDROP=3` |
| 数据 | 临时移出含私人文件名的 13 项（拍完还原）；壁纸拍完切回原图并校验 |

两张测试壁纸由 `tools/phase3-readability.py` 生成（24bit BMP，不依赖第三方库）。

---

## 二、方法（以及它的局限）

1. 把窗口切成 32×32 格，算每格平均亮度 —— 文字笔画在格内占比很小，**格均值 ≈ 该处背景亮度**；
2. 按背景亮度的 p50 / p95 / max 分别计算文字色的 WCAG 对比度
   （sRGB 线性化后的 `(L1+0.05)/(L2+0.05)`）；
3. p95 / max 代表"文字恰好落在最亮处"时的**最坏情况**。

**局限（必须说明）**：这是**全窗口**的百分位，看不出"只垫了一小块底"这种局部改动的效果。
局部效果只能靠裁剪对照图看，见第五节。

---

## 三、结果

正文色 `#F1F5FA`（primary），括号内为 p50 / p95 / 最坏：

| 壁纸 | 窗口 | 背景 p50 亮度 | primary | secondary | tertiary |
|---|---|---|---|---|---|
| 暗 | 全屏分类 | 87.0 | **6.70** / 3.76 / 2.17 | 4.22 / 2.37 / 1.37 | 2.74 / 1.54 / 1.13 |
| 暗 | 悬浮窗 | 140.9 | **3.07** / 2.20 / 1.30 | 1.93 / 1.38 / 1.22 | 1.25 / 1.11 / 1.88 |
| 暗 | 侧边栏 | 70.7 | **8.62** / 3.81 / 3.28 | 5.43 / 2.40 / 2.07 | 3.52 / 1.56 / 1.34 |
| 亮 | 全屏分类 | 107.9 | **4.87** / 3.61 / 2.17 | 3.07 / 2.27 / 1.37 | 1.99 / 1.47 / 1.13 |
| 亮 | 悬浮窗 | 140.9 | **3.07** / 2.12 / 1.30 | 1.93 / 1.34 / 1.22 | 1.25 / 1.15 / 1.88 |
| 亮 | 侧边栏 | 134.0 | **3.33** / 3.03 / 2.28 | 2.09 / 1.91 / 1.43 | 1.36 / 1.24 / 1.08 |

判读（WCAG：正文 4.5、大字/次要 3.0）：

- **暗壁纸 + 全屏分类（主要使用形态）：6.70，合格。**
- **亮壁纸 + 全屏分类：p50 只有 4.87，p95 处掉到 3.61 —— 不合格。**
- **悬浮窗两种壁纸都是 3.07 —— 不合格。** 原因是它面积小、字号小、且（阶段 2 之后）只有一层 18% 基底。
- **侧边栏亮壁纸 3.33 —— 不合格**；暗壁纸 8.62，很好。
- tertiary（提示文字）全程 1.1~3.5：它在设计上就是"弱化"的，但 1.1~1.3 那个档位实质上不可读。

## 四、做了什么修补（只加局部底，不加深面板）

按规格"给文字所在区域增加非常轻的局部背景"，新增 `BrushLabelScrim = #4D000000`（30% 黑），
只垫在**文字本身**下面（小圆角、紧贴字），并且只用在四处"压在玻璃上的名字"：

| 文件 | 位置 |
|---|---|
| `Themes/GlassTheme.xaml` | 新增 `BrushLabelScrim` |
| `Views/ItemTile.xaml` | 项目名（主窗口 / 自由分区的全部瓦片） |
| `Views/FloatingWindow.xaml` | 悬浮窗分类名 |
| `Views/SidebarWindow.xaml` | 侧边栏分类名、项目名 |

**没有做**的（对照规格逐条）：

- ❌ 没有加深 `BrushPanelGlass` / `BrushNavGlass`（"不要直接把整个面板加深"）
- ❌ 没有整体加强 `TextShadowGlass`（"不要无差别增加文字投影强度"）
- ❌ 没有降低窗口 opacity（这是明确禁止的做法）

为什么是 30% 而不是更重：35% 时名字下面会明显变成一条深色胶囊，视觉上开始"像卡片"；
30% 在截图里仍只是很轻的一层，但已足够把字从浅玻璃上"托"起来。

## 五、局部效果验证

`label-before.png` / `label-after.png`（同一位置裁自同一壁纸的同一窗口）：

- before：名字直接压在玻璃上，浅色字与浅背景贴在一起；
- after：名字下面多了一层很轻的深底，字与外圈背景之间出现清晰边界，图标本身没被包进任何卡片。

> 全局百分位指标看不出这个改动（两种版本的数字几乎一模一样），
> 这不是指标出错，而是"整窗 1024 个格子里的 20 来个格子变深"本来就不会移动百分位。
> **局部改动只能按局部看** —— 这也是本报告没有把它算进第三节表格的原因。

## 六、阶段 2 遗留项：悬浮窗圆角外圈有没有"未染色的玻璃"

取悬浮窗左上角 26×26 px 与内部 40~70 px 区域比较平均亮度：

| 壁纸 | 角落均值 | 内部均值 | 判读 |
|---|---|---|---|
| 暗 | 102.5 | 141.8 | 角落偏暗（圆角外露出的是更暗的壁纸），**没有出现亮圈** |
| 亮 | 136.2 | 146.8 | 两者接近，**没有出现未染色的亮边** |

**结论：阶段 2 担心的"圆角外一圈没染色的玻璃"没有出现**，因为 DWM 自己也会裁圆角。

## 七、未解决 / 需要决策

1. **亮壁纸下"非项目名"的文字仍然偏低**：搜索框提示、按钮、状态栏、导航标题都在 3~3.6。
   这些没有垫底（垫了会变成一排深色条，观感更差）。三条可选路线：
   - A. 接受：把"接近纯白的壁纸"列为已知限制（现在的做法）；
   - B. 把窗口基底从 18% 提到 24~26%：全局都会变深，玻璃感下降（阶段 1 已量化，下降明显）；
   - C. 做"背景亮度自适应"：采样窗口背后的平均亮度，动态切浅/深文字色 —— 工作量大，且会引入闪烁风险。
2. **悬浮窗 3.07 最差**：它面积小、字号小，最需要的是"必要时给它一个稍实的底"，
   但那会削弱"小窗也是玻璃"的一致性。建议留到阶段 5 与"侧边栏空分类"一起做产品决策。
3. **本次只测了两张合成壁纸 + 一种 DPI**，没有覆盖照片类壁纸（局部极亮/极暗混合）。

## 九、补充（同日）：控件与状态栏也做了局部处理

上面第七节列的问题里，"搜索框提示 / 按钮 / 状态栏 3~3.6" 已经处理，方法与项目名一致 ——
不加深面板，只给承载文字的那一小块加底：

| 位置 | 改动 | 理由 |
|---|---|---|
| 搜索框 / 全部按钮 | `BrushInputGlass` 从 **7.8% 白** → **30% 深色**（`#4D0A1220`） | 亮壁纸下输入框自己发亮，浅字压上去等于白底白字；规格允许"操作控件更明显" |
| 底部状态栏 | 新增 `StatusBarScrim`（30% 底的圆角条） | 两行统计文字原本直接压在玻璃上 |

**复测（同一套方法、同一组壁纸）**：

| 壁纸 / 窗口 | 改前 primary p50 | 改后 p50 | 改后 p95 |
|---|---|---|---|
| 暗 / 全屏分类 | 6.70 | **7.37** | 3.81 |
| 暗 / 侧边栏 | 8.62 | 8.62 | 4.27 |
| 暗 / 悬浮窗 | 3.07 | **3.15** | 2.20 |
| 亮 / 全屏分类 | 4.87 | **5.01** | 3.71 |
| 亮 / 悬浮窗 | 3.07 | **3.33** | 2.30 |
| 亮 / 侧边栏 | 3.33 | 3.37 | 3.24 |

方向正确、暗背景没有回退；但**亮壁纸 p95 仍在 3.7 左右**——这是"浅色文字 + 半透明玻璃"
的物理上限，靠局部底只能一处处补，要有数量级变化只能改文字色（方案 C）。
