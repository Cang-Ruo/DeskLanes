# 阶段 24：画布不被挤压、底部「全部」两区、拖拽图标反馈

用户三件诉求，按截图里的「示例范围」理解：

> 上方面布要固定占据那块区域、不会缩小；允许下面「全部」覆盖上来；
> 拖软件时下面暂时收起；拖拽时要有软件图标，不要空空如也。

视觉证据：`phase24-panels.png`。

## 一、拖动导致上面缩小和覆盖

**根因**：`FreePanelsView` 顶层是 `DockPanel`，底部「全部」区是
`DockPanel.Dock="Bottom"` 的**实际占位元素**，画布是最后那个 Fill 子元素。
上一轮把底部高度做成可拖之后，往上拖就等于把画布可用高度吃掉——
画布缩放系数跟着变，分区位置/尺寸一起缩，看起来像被覆盖。

**做法**：把工具栏之外的区域改成一个 `Grid`：

- `CanvasHost`（画布）作为 Grid 的第一个子元素**占满整个区域**，不受底部高度影响
- 底部「全部」区改成 `VerticalAlignment="Bottom" Panel.ZIndex="2"` 的**覆盖层**，
  浮在画布之上

于是拖高底部区只是盖住画布下部，画布与分区的尺寸、坐标完全不变。
`CanvasHost.SizeChanged` 的输入也不再随底部高度波动。

## 二、「全部」按文件夹 / 软件分两类、各自 A-Z

`FreePanelsViewModel` 阶段 19 已有 `PoolAppItems` / `PoolFolderItems`（A-Z），
但 XAML 只用了一个 `PoolItems` 单列表。现在改成**左右两栏**：

- 左栏「软件」（2/3 宽），右栏「文件夹」（1/3 宽）
- 两个标题常驻可见，各自独立垂直滚动
- 共用的 `PoolListStyle`（WrapPanel + 右键菜单 + 磁贴）提到资源里复用

> 一开始做成上下堆叠：软件项目多，把「文件夹」整块挤到滚动区外看不见，
> 所以改左右两栏。默认 `PoolPanelHeight` 从 170 提到 250，两栏都露得出来。

## 三、拖软件时暂时收起 + 拖拽图标样式

**收起**：底部覆盖层加 `DataTrigger` 绑 `IsDraggingItem`（来自 `DragState`），
拖拽期间 `Opacity=0.12` + `IsHitTestVisible=False`。
这样它视觉上让开，鼠标落点也能直接穿透到下面的画布/分区，
不会挡住「把软件拖到上面」这个动作。拖放结束自动恢复。
（没有真正折叠成 0 高，避免 `DoDragDrop` 期间拖拽源元素被销毁。）

**拖拽图标**：`ItemTile` 现在在 `DoDragDrop` 之前创建一个跟随鼠标的幽灵窗口——
透明、置顶、`ShowActivated=false`、`IsHitTestVisible=false`、内容是
**软件图标（32×32）+ 名称**。`GiveFeedback` 里用 `MonitorInterop.GetCursorPos`
拿到物理坐标，再用 `CompositionTarget.TransformFromDevice` 换算成 DIP 定位，
拖放结束在 `finally` 关闭。任何异常都不影响拖放本身（创建/关闭都单独 try/catch）。

## 五、仍需用户实测 / 未闭环

1. **拖拽幽灵窗口**：OLE 拖放期间的视觉反馈无法用截图/断言自动化，
   请真的拖一个软件看看图标是否跟着鼠标、拖完是否消失。
2. **「暂时收起」的程度**：现在是淡到 12% 并让鼠标穿透；如果你想要完全隐藏
   或只收成一条标题栏，说一声调。
3. 底部两栏的宽度比例（2:1）是否合适、拖分隔条的手感。
4. 物理热插拔修复复测、真实睡眠唤醒未实测；远程桌面用户暂缓；
   阶段 14 之后新构建 24h+ 驻留未重跑。
