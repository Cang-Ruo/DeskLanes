## 一、分类导航与自由分区合成一份分组数据

**根因**：`ShortcutGroup`（分类导航）和 `WorkspacePanel`（自由分区）是两套独立数据。
用户真实配置里 `Groups` 的「游戏」有 2 个项目，`Panels` 的同名「游戏」是 0 个——
所以在分类导航里分好的东西，切到自由分区看不到。

**做法**（用户选了「合成一份」）：

- `WorkspacePanel` 新增 `GroupId`，与 `ShortcutGroup.Id` 配对
- `ShortcutGroup.ItemIds` 是成员关系的唯一权威；`WorkspaceService.EnsurePairedContainers()`
  把名字和成员镜像到配对面板，新建 / 改名 / 删除 / 成员变更都双向同步
- 构造时 `createMissing: false`：只配对并同步**已有**对象（按 GroupId，旧数据按名字），
  把用户现有「游戏」分类的 2 个项目同步到同名面板，不丢数据、不改变集合数量
- `SetLayoutMode()` 切布局时 `createMissing: true`：给没有配对的另一边补建，
  于是「在分类导航建游戏 → 切自由分区自动出现游戏面板」，反之亦然
- 删除任一边时配对的一边一起删；成员项目仍留在「全部」里

> 一开始把补建放在每次 CRUD 后，冒烟立刻掉了 8 项（集合数量变了）。
> 改成只在切布局时补全后，既有行为不受影响，用户看到的效果一样。

## 二、「全部」取代「未分组 / 未分区项目」

| 位置 | 原来 | 现在 |
|---|---|---|
| 分类导航首节点 | 未分组（只显示未归类） | **全部**（所有项目，含已分组的） |
| 自由分区底部池 | 未分区项目（N） | **全部（N）**，含已加入面板的 |
| 悬浮窗「全部」 | 原本就显示所有项目 | 保留，按下面两区呈现 |

「分组好的也不会从全部里面消失」由冒烟断言锁住。

**文件夹 / 软件两区 + A-Z 排序**：分类导航（阶段 14 已有两区）、
悬浮窗「全部」视图、自由分区「全部」的项目都按名称排序，
文件夹（桌面文件夹项目）与软件（其余）分区各按 A-Z
（`StringComparer.CurrentCultureIgnoreCase`，中文按当前文化拼音序）。

## 三、悬浮窗两种视图

顶部新增「文件夹视图 / 全部视图」切换按钮：

- **全部视图**：项目区拆「文件夹」「软件」两区，各自 A-Z；
  顶部分类标签保留（可点某个分类筛选），「全部」显示真实总数
- **文件夹视图**：只显示**分组卡片**（📁 名称 + 项目数），
  不把里面的文件平铺出来——例如「游戏」有 2 个项目，只显示一张「游戏」卡片；
  点卡片才列出成员，顶部出现「← 返回」

`FloatingViewMode` 状态机 + `FloatingFolderCard` + `OpenFolderCommand` /
`BackToFoldersCommand`；卡片视图不显示「无项目」空状态。
`UiSnapshot` 新增 `floatingfolders` 模式便于回归截图。

## 四、自由分区拖拽修好

**根因**：`PanelView.xaml` 里带 `AllowDrop` 的项目 `ListBox` 绑了
`Visibility="{Binding HasItems}"`——**空面板时控件被折叠，根本没有拖放目标**，
所以底部项目拖不进新建的分区。

**修法**：把 `AllowDrop / Drop / DragOver` 同时挂到根 `Border`（始终可见）。
非空面板时内层 ListBox 先处理并 `Handled=true`，不会重复触发；空面板时由根 Border 接住。
底部提示文案改成「全部项目都显示在这里（含已加入分区的）；把项目拖到上方分区即可加入」，
面板右键菜单「放回未分区池」改为「从分区移出」。
