# 阶段 22：全屏跟随当前显示器、消除模式切换闪烁

用户反馈两件事，均已定位并修复。

## 一、全屏固定落在左边竖屏，拖悬浮窗到主屏也没用

**根因**：`MainWindow` 靠 `WindowStartupLocation="CenterScreen"` + `WindowState=Maximized`。
WPF **按窗口当前所在的那块显示器**最大化，位置由窗口自身坐标决定，和用户把
悬浮窗拖到哪块屏完全无关。多屏（主屏 + 左竖屏 + 右屏）下窗口一旦落在虚拟屏
左侧，最大化就固定在左竖屏。

**做法**：`MonitorInterop` 增加 `GetCursorPos` / `MonitorFromPoint` /
`GetMonitorInfo` / `SetWindowPos` 封装，`MainWindow.PlaceOnCursorMonitor()` 在
`ApplyMode(Full)` 显示窗口**之前**：

1. 取鼠标当前所在显示器的工作区（物理像素，避开混合 DPI 下 DIP 位置换算不准）
2. `SetWindowPos` 把窗口移到该屏工作区左上角
3. 再 `WindowState = Maximized`

这样「鼠标在哪块屏操作，全屏就开在哪块屏」：把悬浮窗拖到主屏、在那里点
「全屏」或托盘菜单，全屏就在主屏。切到全屏之前就完成定位，也顺带避免
先闪一帧普通尺寸窗口。

**实测**（新安装版、临时把配置改成 `WindowMode=1` 后启动，鼠标分别放在两块屏）：

```
鼠标在主屏   (1280,720)  -> MainWindow [(0,0,2048,1152)]  中心x=1024  -> 主屏
鼠标在左竖屏 (-540,1000) -> MainWindow [(-864,292,-144,1572)] 中心x=-504 -> 左竖屏
settings.json restored byte-exact: True
```

（坐标是未设 DPI 感知时的虚拟化值；物理上主屏 2560×1440。）

## 二、全屏切侧边栏「闪一下，很明显」

两个叠加的原因：

1. `AppController.ApplyMode()` 三个分支都是**先 `Hide()` 另外两个窗口，再 `Show()` 当前窗口**，
   中间有一帧所有窗口都不可见，桌面整个露出来。
2. 阶段 21 为修首次空白灰块，在 `ShowDocked()` 里加了
   `Dispatcher.BeginInvoke(...Loaded)` 显示后**再定位一次**，窗口会先出现在旧位置再跳到新位置。

**做法**：

- 三个分支统一改成**先显示并布置新窗口，最后才隐藏旧窗口**，任意时刻至少有一个窗口可见。
- 去掉 `ShowDocked()` 的显示后二次定位；`PlaceOnDockedSide()` 改用
  `MonitorInterop.TryGetWorkAreaForDockedSide()`（按虚拟屏最左/最右物理坐标取屏，
  **不依赖尚未创建的 HWND**），在 Show 之前一次定位到位，兼顾「占满屏高」与「不跳」。
