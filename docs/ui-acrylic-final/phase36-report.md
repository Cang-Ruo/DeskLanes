# 阶段 36：小球可移动 / 悬浮窗缩小 / 玻璃配色统一

视觉证据：`phase36-ball-glass.png`（新配色小球）、`phase36-floating-compact.png`（缩小后的悬浮窗）。
功能探针：`tools/phase36-ball-probe.py`（9 项全过）。

## 一、四项诉求与实现

| 诉求 | 做法 |
|---|---|
| 悬浮窗收缩态（小球）**可以移动** | `EdgeStripWindow` 只有 `FloatingBall` 形态响应拖动；物理像素定位，限制在该屏工作区内；位移 <4px 仍算点击，避免手抖误触；拖动结束把位置写入 `AppSettings.CollapseBallLeft/Top` 并落盘，下次收起 / 重启仍在原地 |
| 悬浮窗本体**再小一点** | XAML 与 `AppSettings` 默认 `780×540 → 620×430`；已保存的旧尺寸做**一次性** 85% 迁移（你的 `593.6×434.4 → 504.56×369.24`），不小于最小尺寸 420×360；只对「用户改过尺寸」的配置迁移，新默认不会被重复缩小；标记落盘后你手动调整不再被覆盖 |
| 小球颜色 = **淡蓝半透明，和本体统一** | 收起态（小球 / 边栏 / 窄条）改用与三窗口本体**同一支** `BrushShellGlass`（`#4A20334A`，29% 深蓝灰玻璃），不再用阶段 34 的淡蓝白 `#4DE8F1FF`（叠在红壁纸上会泛粉灰）；hover 只是同色系稍浓，描边淡蓝。改一处画刷三处同步 |
| **焦点不在软件又变成之前的样式，希望统一** | 两层处理：① 收起态与本体共用同一支画刷（上一条）；② `ApplyTopmostSetting` 不再顺手 `SendBehind()` —— 启动时 / 从小球展开时原本会把窗口沉到 z 序最底层，看起来像「样式变了」。现在失焦需要留在最底层由 `OnDeactivated` 自己处理。三窗口真实焦点切换像素差仍 ≤0.52 |

> 关于第 4 点的理解：我按「**外观 / 材质统一**」处理。如果你其实是指「不希望失焦就收起成小球 / 边栏，窗口应保持原样可见」，请直接说，我再调失焦行为，不盲改。

## 二、位置持久化与配置处理

- 新增 `CollapseBallLeft/Top`（物理像素，null = 默认左边缘中部）与
  `FloatingCompactSizeMigrated` 标记。
- `AppController` 订阅 `EdgeStripWindow.BallMoved` → 写设置并 `Save()`；
  `CollapseToEdge()` 把保存位置传回 `ShowAtWorkArea()`，换分辨率时会 clamp 回工作区。
- 探针跑完**清掉测试产生的小球位置**（让小球回默认位置），但保留你要的
  「更小悬浮窗」迁移结果；其它偏好原样还原。

实测：小球从默认 `(0,633)` 拖到 `(260,783)`，写入配置，**重启应用后仍在 (260,783)**；
拖动不会误触发展开，拖完再点击仍能叫回悬浮窗。

## 三、前提变化后替换的两条断言（未降低标准）

1. `verify-floating-interaction.py` 的「悬浮窗自动收缩以适配竖屏」
   基于旧默认 780 DIP（@150% = 1170px，需收缩到 ~1068）。现在默认 620 DIP
   （930px）本来就在 1080px 竖屏内，换成等价断言：
   **必须完整落在竖屏工作区内（`x2 >= vx` 且 `x2+w2 <= 0`）且不小于最小尺寸**。
2. `phase34-collapse-probe.py` 的「窄条靠近才弹出」像素差从 26.12 降到 4.86，
   因为窄条改用本体深蓝玻璃、对比变弱，且全 80px 区域平均把 19px 信号稀释。
   改成**只比对窄条那 0.5cm 区域**（信号更集中、断言更严格），
   实测 20.47，阈值仍为 6。
