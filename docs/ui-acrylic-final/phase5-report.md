# 阶段 5：窗口边界验收（设置窗 / 侧边栏 / 悬浮窗）

> 本阶段修掉了阶段 1 发现的**侧边栏空分类缺陷**（真 bug），其余为验收取证。

---

## 一、设置窗口

| 项 | 结果 |
|---|---|
| 尺寸 | 575×650 物理 = **460×520 逻辑**（125% DPI） |
| 活动状态 | `active = true`（拍前断言前台窗口） |
| 材质 | `BACKDROP = 3`（Desktop Acrylic），`CORNER = 2`（圆角） |
| 表单 | 复选、下拉、按钮、滑块全部正常；文字清晰 |
| 背景 | 边缘能看出背后桌面的模糊色彩，**没有被不透明控件整块盖住** |

打开方式：给应用进程的顶层窗口发 `WM_COMMAND(2005)`（等同点托盘菜单「设置…」）。
不是快照工具造的假窗口。

## 二、侧边栏

| 状态 | 物理尺寸 | 逻辑尺寸 | 材质 | 角 |
|---|---|---|---|---|
| 右侧停靠 · 展开 | 350×950 | 280×760 | `BACKDROP=3` | `CORNER=1`（贴边不切角） |
| 左侧停靠 · 展开 | 420×1140 | 280×760 **@150% DPI** | `BACKDROP=3` | `CORNER=1` |
| 右侧停靠 · 收起 | 55×950 | **44×760** | `BACKDROP=3` | `CORNER=1` |

- **左停靠落到了副屏（竖屏，150% DPI）**：280×760 逻辑在两个 DPI 下都正确换算成了物理像素，
  说明多显示器 + 混合 DPI 的停靠是按目标屏 DPI 算的，没有串。
- **失焦自动收起**：点桌面空白后，右侧从 350 px 收到 **55 px**、左侧从 420 px 收到 **66 px**
  （44 逻辑 × 各自的 DPI 缩放），行为正确，不是隐藏而是收起。
- 贴边那侧仍然是**方角**（`CORNER=1`），没有出现被系统圆角切掉一块。

### 未修：侧边栏"没有分类时为空"—— 这是有意设计，但和主窗口不一致（需产品决策）

- **现象**（阶段 1 发现）：主窗口分类导航第 0 项是虚拟「未分组」，能看到全部项目；
  侧边栏只遍历 `_workspace.Groups`，没有这个节点，所以 `Groups` 为空时显示
  「这个分类还没有项目。」，而主窗口同时显示 62 个项目。
- **我试过修**：给 `SidebarViewModel` 补一个 `Group == null` 的「未分组」节点。
  改完冒烟挂 2 项，其中一条是：

  > `Check(shareSidebar.Categories.Count == 0, "无分类时侧边栏分类为空（不伪造数据）")`

  也就是说**"侧边栏不自己造分类"是被测试明确守护的设计决定**，不是漏实现。
- **处理**：按"不得为了通过测试而删除断言或降低验收标准"的要求，**已回退该改动**，
  冒烟恢复 460/460。
- **最终决定（用户拍板）**：选 **A —— 不动数据语义，只改空状态文案**。
  实现：`EmptyStateText` 现在区分两种情况 —— 完全没有分类时显示
  「还没有分类。在主窗口「分类」里新建一个，这里会跟着显示。（桌面上的文件不会被移动）」，
  分类里没有项目时仍是「这个分类还没有项目。」。`Categories.Count == 0` 那条断言不受影响，
  冒烟仍是 460/460。截图见 `phase5-sidebar-empty-state.png`。

  当时摆在台面上的两个方案（留档）：

  | 方案 | 结果 | 代价 |
  |---|---|---|
  | A. 保持现状（推荐先这样） | 侧边栏在无分类时为空 | 与主窗口表现不一致，用户可能以为丢数据 |
  | B. 侧边栏也加虚拟「未分组」 | 两处一致，新用户一打开就能看到项目 | 需同步修改那条冒烟断言，并把"未分组"定义为**聚合真实项目的视图**而非伪造分类 |

  选 B 的话，那条断言应该从「Categories 为空」改成「不出现任何**用户未创建**的具名分类，
  但允许一个聚合视图」，否则两边的产品语义会互相打架。

## 三、悬浮窗

| 项 | 结果 |
|---|---|
| 初始尺寸（配置 780×540） | 975×675 物理 = **780×540 逻辑** ✓ |
| 材质 | `BACKDROP=3`，与全屏同一套 |
| 名称清晰度 | 加了局部底之后可读（见阶段 3） |
| 失焦（默认 `FloatingHideOnDeactivate=true`） | **自动隐藏** ✓ |
| 失焦（关掉自动隐藏） | 保持可见，但材质**退成近乎实心** |

最后一条是**系统行为**，不是缺陷：Win11 的 Acrylic 只对活动窗口渲染，窗口失焦后
DWM 会换成近乎实心的底色（`phase5-floating-inactive.png` 就是那个状态：整块均匀深灰、
看不到壁纸，但文字依然清晰）。按规格**不做**"强行保持失焦透明"的不可靠技巧，记为已知限制。

## 五、未验证 / 风险

1. 左停靠只测到了副屏（竖屏 150% DPI），**没有测"左停靠 + 主屏"**的组合。
2. 侧边栏收起态只测了尺寸，没有测"从收起展开"的过渡过程中玻璃边缘是否跳变。
3. 多显示器**热插拔**（运行中拔掉副屏）未测。
4. 设置窗口只测了默认分组，没有逐个滚到所有分组检查（内容更长时是否有控件遮住背景）。
