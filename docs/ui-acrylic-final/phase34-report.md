# 阶段 34：三种模式各自的收束形态

用户规格（其中三处细节经确认）：

- **侧边栏**收起后是 **0.5cm 半透明边栏**，鼠标移上去就展开、移开自动收束；
- **悬浮窗**收起是 **直径 3cm 的半透明小球**，放在**屏幕左边缘中部**、**点击**展开；
- **全屏**收起后默认不显示东西，**鼠标靠近左边屏幕边界**才弹出 **0.5cm 宽、铺满工作区高度** 的半透明小窄条，**点击**才展开全屏。

视觉证据：`phase34-{sidebar-bar,floating-ball,full-hidden,full-strip}.png`；
功能探针：`tools/phase34-collapse-probe.py`（19 项全过）。

## 一、实现

新增 `CollapseVisualPolicy`（纯函数，冒烟直接覆盖）统一表达尺寸与交互策略：

| | 可见玻璃 | 窗口热区 | 位置 | 展开方式 |
|---|---|---|---|---|
| 侧边栏 `SidebarBar` | 0.5cm ≈ 19px，半透明常驻 | 2 倍宽 ≈38px | 工作区最左，全高 | 悬停即展开 / 移开收束 |
| 悬浮窗 `FloatingBall` | 直径 3cm ≈ 113px 半透明圆 | 同直径 | 左边缘中部 | 点击展开（悬停只提亮） |
| 全屏 `FullStrip` | 0.5cm ≈ 19px，**默认隐藏** | 2 倍宽 ≈38px，全高 | 工作区最左 | 靠近边界弹出窄条 → 点击展开 |

- 一个 `EdgeStripWindow` 承载三种形态：`Bar`（边栏/窄条）+ `Ball`（圆），
  按 `CollapseVisual` 切换可见性、窗口尺寸与位置；全部用物理像素 +
  `SetWindowPos` 定位，混合 DPI 不会跑偏。
- 全屏的「靠近才弹出」：热区常驻（38px、透明、Topmost），
  `MouseEnter` 才把可见窄条显示出来，`MouseLeave` 再隐藏；
  点击窄条才展开。**悬停本身不会展开工作空间**（探针已验证）。
- 悬浮窗从「沉到焦点软件后面」改成真正收起：
  `OnItemLaunched` / Esc / 热键统一走 `CollapseToEdge()`，
  窗口隐藏、小球出现；点击小球 `ShowAndActivate()` 叫回原窗口。
  `HideFloating()` 在收束态下不再改 ModeManager 可见状态，避免热键误判。
- Esc 现在三种模式都先收束（关掉「自动收起」时沿用隐藏到托盘）；
  设置文案同步更新为新形态。

## 二、为什么热区是可见玻璃的两倍

两个原因，探针实测确认：

1. 鼠标「靠近」左边界就触发，而不是精确压在 19px 上，好用得多；
2. 侧边栏停靠在 **150% DPI 的左侧竖屏**时，19px 窗口被 WPF 折算成 23px、
   38px 热区变 46px（`GetWindowRect` 含系统边框）。把可见玻璃固定为
   `Bar.Width = 19px / dpiScale`、窗口用更宽热区，视觉尺寸仍精确 0.5cm，
   不受 DPI 折算影响。

因此探针验证的是「可见玻璃恒 0.5cm（冒烟锁定 `BarPixels == 19`）
+ 热区比可见边栏宽」，而不是硬卡窗口 rect 的 38px。

## 五、仍需用户实测

1. 三种收起形态在你的竖屏上是否够「半透明、不碍眼」；
2. 全屏窄条「靠近才弹出」的触发范围（38px）是否顺手；
3. 小球放在左边缘中部是否是你想要的位置；
4. 侧边栏悬停即展开、悬浮窗/全屏点击展开的节奏是否合适。
