## 二、玻璃材质到底成不成立（阶段 1）

- 属性读回：四个窗口全部 `BACKDROP=3`（Desktop Acrylic），不是"设了没渲染"；
- 全屏下窗口内容与背后桌面的**结构相关 0.909**，窗口 std 24.0 / 桌面 std 89.5（保留比 **0.27**）；
- 强制不透明对照组相关系数 0.105。
- **结论：材质真实生效**；全屏看着"平"是因为背后只剩深色低对比壁纸，不是材质失效。
- 顺带确认：`Full` 模式下 `WindowMaximized=false` 无效（应用自己最大化）。

## 七、未解决问题与风险（必须一起看）

### 1. 待产品决策：侧边栏"无分类时为空"

- 主窗口有虚拟「未分组」能看到全部项目；侧边栏没有，`Groups` 为空时显示"还没有项目"。
- 这不是漏实现：冒烟里有一条 `无分类时侧边栏分类为空（不伪造数据）` 在守着。
- 我试过补虚拟节点，冒烟挂 2 项，已按"不得改断言迁就代码"**回退**。
- 方案 A 保持现状 / 方案 B 加聚合视图（需同时改那条断言），取舍见 `phase5-report.md`。

### 2. 亮壁纸下非项目名文字仍偏低（3~3.6）

搜索框提示、按钮、状态栏没有垫底（垫了会变成一排深色条）。三条路线（接受 / 提基底 / 自适应）见 `phase3-report.md` 第七节。

### 3. 悬浮窗两种壁纸都只有 3.07

面积小、字号小、基底 18%。要救就得给它更实的底，会削弱"小窗也是玻璃"的一致性。

### 4. 已知限制（系统行为，非缺陷）

- **失焦后 Acrylic 退成近乎实心**：Win11 只对活动窗口渲染材质，文档化在 `phase5-report.md`；
- **无虚拟化**：内存随项目数线性涨，500 项目会更重（架构层问题，未在本轮处理）。

### 5. 测试覆盖的空白

单机、单壁纸组合、单一 DPI（125%）；副屏只有竖屏 150%；未测显示器热插拔、锁屏/睡眠恢复、跨天驻留。

## 八、基线声明

在下列前提下，把当前轻玻璃主题标记为**设计基线**：

1. 材质：`Desktop Acrylic` 优先 → 被拒退 `Mica` → 再退不透明（`WindowBackdropService`）；
2. 层次：窗口基底 18% / 导航 30.2% / 内容 20% / 卡片 25.1%，**不再叠加重复层**；
3. 文字：浅色主文字 + 1px 级投影，名字另加 30% 局部底；
4. 四个窗口（主窗 / 悬浮 / 侧边栏 / 设置）共用同一套材质与参数，侧边栏贴边方角。

后续若要改这一层，必须重跑 `tools/phase2-ab.py` 与 `tools/phase3-readability.py`，
否则无法证明"改动没有把玻璃或可读性弄坏"。
