# 阶段 31：全屏露任务栏、启动后收束成左侧细线、全屏磁贴缩到 80%

视觉证据：`phase31-{tiles-80,edge-strip,taskbar-visible}.png`。
功能探针：`tools/phase31-collapse-probe.py`（8 项全过）。

## 一、全屏不再盖住任务栏

`MainWindow` 的 `WindowState.Maximized` 原本会把无边框窗口铺满整块显示器，
连任务栏一起盖掉。在 `SourceInitialized` 里挂 `WM_GETMINMAXINFO`，
把「最大化尺寸 / 位置」改成该显示器 `MONITORINFO.rcWork`：

- 仍是系统意义的最大化（`showCmd=3`），不影响还原、多屏定位、窗口偏好；
- 高度等于工作区高度。实测：显示器 1920、工作区 1848、窗口 1848，
  底部 72 px 任务栏完整可见（`phase31-taskbar-visible.png`）；
- 端到端新增等价断言 `fullscreen leaves the taskbar visible`，36 → **37 项**。

## 二、双击打开软件后自动「收束」

**触发**：`ShellState.ItemLaunched` —— 五个视图模型（主窗口 / 分类导航 /
自由分区 / 侧边栏 / 悬浮窗）在 `Launch` 成功后统一发事件；启动失败不收束，
方便用户看错误提示继续操作。`AppController` 订阅后按模式处理。

**收束样式**：新增 `EdgeStripWindow` —— 屏幕工作区最左侧一条 2 DIP 的淡线，
外层 8 DIP 是鼠标命中区，`Topmost` + 不进任务栏 + 不抢焦点，
不会挡住刚打开的软件。截图 `phase31-edge-strip.png`。

| 模式 | 收束行为 | 展开方式 |
|---|---|---|
| 全屏 | 主窗口隐藏，只留细线 | **鼠标移上去只提亮，必须点击**才展开 |
| 侧边栏 | 侧边栏隐藏，只留细线 | **悬停即展开**（不抢焦点），鼠标移开自动收束 |
| 悬浮窗（特例） | 不走细线，沉到焦点软件后面 | 原生窗口，没被藏掉 |

- 侧边栏悬停展开后由 350 ms 定时器用 Win32 `GetCursorPos` + `GetWindowRect`
  做几何判定，指针离开侧边栏区域才收束；用户点进侧边栏（窗口获得焦点）
  则保持展开不自动收。避免 WPF 在「窗口突然出现在鼠标下方」时
  `IsMouseOver` 不稳导致刚展开就收回。
- 从细线展开全屏时**回到收束前那块显示器**（`_collapsedWork`），
  不按鼠标所在屏 —— 鼠标正停在左边缘，容易被 `MonitorFromPoint` 判到相邻左竖屏。
- Esc 现在也是「收束」入口（全屏与侧边栏一致）；关掉自动收束时沿用原来
  「隐藏到托盘」。快捷键在全屏 / 侧边栏模式下改为「打开当前工作空间」
  （收束着就展开，展开着就带到前台），不再把用户切到悬浮窗模式。
- 新增设置 `CollapseOnLaunch`（默认开）、`FloatingTopmost`（默认关，
  即藏到焦点软件后面；打开则常驻置顶）。托盘点设置、模式切换都会先退出收束态。

## 三、透明度保持不变

本轮**没有改动任何透明度 / 材质代码**：

- 侧边栏维持阶段 30 的分层窗口方案（WPF 自绘半透明，两态一致）；
  悬停展开不激活窗口，看到的就是同一套「焦点态」玻璃。
- 全屏仍是 DWM Acrylic；点击细线展开会激活窗口，呈现的正是
  「DeskLanes 为焦点」的透明度。收束态只剩一条细线，不存在透明度假象。

## 四、全屏磁贴缩到 80%

- `ItemTile` 新增 `TileScale` 依赖属性，用 `LayoutTransform` 等比缩放，
  父容器按缩放后尺寸排版，图标 / 名字牌 / 文字一起缩，不错位。
- `MainWindow.Resources` 里给 `ItemTile` 设 `TileScale=0.8`；
  悬浮窗与侧边栏仍是 1.0（用户只提全屏太大）。
- 图标原本就有 `BitmapScalingMode=HighQuality`，缩小后更锐利，
  同时 `AutoFitPanel` 常量同步 80%（96→77、92→74、40→32、16→13），
  分区框仍刚好包住所有软件。截图 `phase31-tiles-80.png`。
- 用户手动拖过的分区尺寸仍不重算（阶段 26 的规则保留）。
- 冒烟里阶段 26 那条「成员变多时框不会变小」以旧默认高 240 为基准，
  80% 缩放后前提失效；**替换为更严格的等价断言**：
  6 成员高度 > 1 成员高度，不依赖任何绝对像素。

## 六、仍需用户实测 / 未闭环

1. 「双击打开软件 → 自动收束」在真机上的手感（功能探针用 Esc 走的是
   同一个收束入口，`ItemLaunched` 链路已由单元测试覆盖，但没真的启动你的软件）。
2. 细线是否足够「不明显」、悬停 / 点击的触发范围是否顺手。
3. 80% 磁贴在你的分辨率下是否合适（还嫌大可以继续调 `TileScale`）。
4. 全屏露出任务栏后，工作区高度变小是否影响自由分区排布。
5. 长期：物理热插拔复测、真实睡眠唤醒、阶段 14 之后新构建 24h+ 驻留、
   远程桌面会话；Windows 更新后的 explorer.exe DLL 报错是否消失。
