# 阶段 33：侧边栏与悬浮窗统一为同一套玻璃

用户在竖屏上并排对比后指出：希望侧边栏与悬浮窗是「一样的感觉」，
但侧边栏明显不如悬浮窗「简洁透亮」。

视觉证据：`phase33-sidebar-glass.png`、`phase33-floating-glass.png`
（两个窗口强制摆到同一屏幕位置、同一尺寸 500×600 的真实屏幕合成截图）。

## 一、根因：两条完全不同的 tint 配方

| | 悬浮窗（用户喜欢） | 侧边栏（用户不满意） |
|---|---|---|
| `Window.Background` | `#2020334A`（12.5% 深蓝） | `#01000000`（≈0，几乎全透） |
| 根 Border | `BrushWindowBaseGlass` `#4A20334A`（29% 深蓝紫） | `BrushSidebarBaseGlass` `#10E8EEF5`（6% **白**） |
| 合计效果 | ≈38% **深色** → 红壁纸被压暗、白花清晰透出 | ≈8% **白色** → 红壁纸被提亮成粉白雾面、显浑浊 |

两者虽然都走同一个 `WindowBackdropService.ApplyLayeredWindow`
（backdrop `NONE` + 窗口级 Acrylic tint `0x06FFFFFF`），
但 WPF 自己画的那两层 tint 完全不同，所以观感是两种材质。

**方向性纠错**：阶段 32 把用户说的「太明显、不清新」误读成「要更透」，
于是把侧边栏的白 tint 一路降到 8%，结果变成浅色雾面；
用户真正喜欢的是悬浮窗那种**深色半透明玻璃**。

## 二、做法：一个共享配方，代码层面锁死

- `GlassTheme.xaml` 新增 **`BrushShellGlass` `#4A20334A`**，
  作为两个分层窗口唯一的根玻璃画刷；删除 `BrushSidebarBaseGlass`
  （侧栏专用浅白玻璃，不再有第二条配方）。
  历史键 `BrushWindowBaseGlass` 保留为同色兼容别名。
- `SidebarWindow.xaml`：窗口底色 `#01000000` → **`#2020334A`**（与悬浮窗一致），
  根 Border 改引用 `BrushShellGlass`。
- `FloatingWindow.xaml`：根 Border 也改引用 `BrushShellGlass`。
- 三个窗口（含全屏）仍共用 `WindowBackdropService` 的窗口级 Acrylic 与
  `NONE` backdrop，焦点两态一致性不受影响。
- 新增冒烟第 40 节 **6 条一致性守卫**（文本级）：共享画刷存在且颜色正确、
  两个窗口引用同一画刷、两个窗口底色相同、侧栏专用浅白玻璃已移除、
  历史键与共享键同色。防止以后又各调各的。

## 三、客观验证

`tools/phase33-glass-parity.py` 把两个窗口用 `SetWindowPos` 摆到
同一坐标 (100,100)、同一尺寸 500×600，各自做 GDI 屏幕合成截图，
比较窗口内底部空白玻璃条的平均 RGB：

```
sidebar  [85.1, 76.6, 90.3]
floating [94.7, 81.6, 85.9]
mean_rgb_delta = 6.33   →  配方一致（阈值 12）
```

剩余 6.33 来自窗口级 Acrylic 模糊采样范围不同与内容残留，
不是 tint 差异。人工看图确认：两张都是深紫灰半透明玻璃，
红壁纸被压暗、白花模糊透出，侧栏不再是粉白雾面。

## 五、仍需用户实测

1. 竖屏下侧边栏与悬浮窗现在是否「一样的感觉」；
2. 深色玻璃在亮壁纸 / 白底软件上的白字可读性；
3. 若还想更透或更暗，只改 `BrushShellGlass` 一处即可（两边会同步）。
4. 长期：物理热插拔复测、真实睡眠唤醒、阶段 14 之后新构建 24h+ 驻留、
   远程桌面会话。
