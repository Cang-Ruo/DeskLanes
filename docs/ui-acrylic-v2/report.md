# 轻玻璃改版（第二轮）：实测、改动与验收

> 目标：把 DeskLanes 从「一块深色软件窗口」改成「桌面上浮现的一层半透明磨砂玻璃工作空间」。
> 这份文档只记录**能复现的实测**与**改了什么**，不写"应该更好看了"这类没有依据的话。

---

## 一、先回答那个问题

**现在的 DeskLanes 打开时像什么？**

在**桌面有内容、窗口处于活动状态**时：像一层浮在桌面上的半透明玻璃——壁纸的颜色、桌面图标的模糊轮廓会透进窗口里，
左侧导航是一块独立的半透明面板，项目区是压在它上面的一层玻璃。

但它**不是**「在任何背景下都一眼看出很透」的效果，原因见第二节第 3 条：
Windows 自己给的透光量有限（实测约 1/3），而且**非活动窗口会被系统换成近乎实心的底色**。

所以更准确的说法是：

| 场景 | 观感 |
|---|---|
| 活动窗口 + 壁纸有明暗变化 | **是玻璃**：能看出壁纸的颜色与模糊轮廓 |
| 活动窗口 + 背后是纯色/纯黑 | 玻璃感很弱，看起来接近半透明色块（系统只给这么多） |
| 窗口失焦（点了别处） | 系统把材质换成近乎实心——这不是我们的 bug，是 Win11 的行为 |

## 二、三个决定性的实测结论

### 1. 材质确实生效，不是"设了但没渲染"

在活动窗口上直接读回 DWM 属性（`DwmGetWindowAttribute`）：

| 窗口 | `DWMWA_USE_IMMERSIVE_DARK_MODE`(20) | `DWMWA_SYSTEMBACKDROP_TYPE`(38) | `DWMWA_WINDOW_CORNER_PREFERENCE`(33) |
|---|---|---|---|
| 主窗口 | 1 | **3 = Desktop Acrylic** | 2 = 圆角 |
| 设置窗口 | 1 | **3** | 2 |
| 输入对话框 | 1 | **3** | 2 |
| 侧边栏 | 1 | **3** | **1 = 不做圆角**（贴边用） |

> 注意：`CAPTION_COLOR`(35) / `BORDER_COLOR`(34) 只能写、不能读（读回一律 `0x80070057`），
> 所以这两项没法用读回验证，只能看截图。

### 2. 定量对照：窗口内容确实跟着背后桌面走

用一个**只贴材质、没有任何 UI 内容**的参照窗口（`UiSnapshot reference`）取证：

| 指标 | 玻璃窗口 | 不透明对照（强制 `BACKDROP=none`） |
|---|---|---|
| 与背后桌面的结构相关系数 | **0.534** | 0.105 |
| 窗口内亮度标准差 | 3.3 | — |
| 背后桌面自身的亮度标准差 | 12.1 | — |
| 窗口内高频锐度 | 1.10 | — |
| 背后桌面高频锐度 | 5.28 | — |

读法：
- 相关系数 0.53 vs 0.10 → 玻璃窗口的明暗**跟着背后桌面走**，不透明窗口不跟。这是"透光"的直接证据。
- 高频锐度 1.10 vs 5.28 → 透进来的是**模糊后**的内容，不是把背景清晰贴上来。
- **但**窗口内的起伏只有背景的 **3.3 / 12.1 ≈ 27%** —— 这就是"能看出来，但不会很夸张"的原因。

### 3. 真正把玻璃吃掉的，是我们自己叠的 tint

每一层带 α 的底色都是**乘法衰减**：`透光 = (1-α₁)(1-α₂)(1-α₃) × 系统给的那部分`。

之前三层叠加（窗口 18% + 导航 35% + 面板/卡片）时，系统给的 27% 会被再打掉一半以上，
这就是"明明用了 Acrylic，看起来还是一块深色实心矩形"的**主因**——不是材质没生效，是我们在上面糊了三层。

### 4. 一个容易踩的坑：非活动窗口没有玻璃

Win11 的 Acrylic 只对**活动窗口**渲染；窗口一失焦，系统会把它换成近乎实心的底色。
第一版取证脚本没让窗口拿到焦点，拍出来全是平板——**看起来像"材质没生效"，实际是拍法有误**。
现在 `tools/shoot-window.py` 会先合成点击把窗口点成活动窗口，并断言 `GetForegroundWindow() == hwnd` 再拍。

## 三、这次改了什么

| 文件 | 改动 |
|---|---|
| `Themes/GlassTheme.xaml` | tint 全部压薄并写清"乘法衰减"的理由：窗口基底 18%→**18%**（保留）、导航 35%→**30%**、面板 14%→**20%**、卡片 24%→**25%**；新增 `TextShadowGlass`（1px 偏移、小半径）与 `ItemNameText` / `ItemNameTextTight` 两个文字样式 |
| `Views/ItemTile.xaml` | 项目名改用 `ItemNameText`（带极轻投影），字号/图标尺寸维持 13 / 48 DIP |
| `Views/CategoryNavView.xaml` | 分类名改用带投影的样式；**项目区外面套一层玻璃面板**（`GlassPanel`），形成「窗口基底 / 导航面板 / 内容面板」三层结构 |
| `Views/SidebarWindow.xaml` | 分层窗口 → **WindowChrome 非分层窗口**；根 Border 背景绑 `Window.Background`（跟主窗口同一套材质）；去掉已无意义的 `DropShadowEffect` |
| `Views/SidebarWindow.xaml.cs` | 构造里 `WindowBackdropService.Attach(this, squareCorner: true)` |
| `Services/WindowBackdropService.cs` | `Attach/Apply` 增加 `squareCorner` 参数（贴边窗口不做系统圆角，避免贴边那侧被切成缺角） |
| `Core/Native/DwmInterop.cs` | 新增 `CornerPreferenceDoNotRound = 1` |
| `tests/DeskLanes.UiSnapshot/Program.cs` | 新增 `reference` 模式（只贴材质的参照窗口）、`--keep-size`（窗口化取证）、`--hold=N`（截图后保留窗口供外部取参照帧）；`--screen` 时窗口可激活 |
| `tools/shoot-window.py` | **新**：把真实窗口摆到指定位置/尺寸、点成活动窗口、清场（最小化其它窗口）后截窗口矩形 |
| `tools/glass-proof.py` | **新**：定量取证（结构相关 / 唯一色 / 高频锐度），带强制不透明对照组 |
| `tools/glass-causal.py` | **新**：因果实验（换掉背后内容看窗口跟不跟）。**当前版本不可靠**，见"未验证"第 3 条 |

### 为什么文字要加投影，而不是把面板加深

玻璃一旦真透光，浅色文字压在亮背景上必然糊。把面板加深来救，就等于把玻璃又糊成实心。
所以对比度交给**1px 级别的文字投影**（`TextShadowGlass`：BlurRadius 3 / ShadowDepth 1 / Opacity 0.55），
面板保持通透。这是玻璃 UI 的常规解法，不是"发光边框"。

## 六、未验证 / 已知风险（如实列出）

1. **文字对比度没有客观判据**：目前靠截图目测。亮背景（白底窗口在后面）时正文对比度偏低，
   投影能救回一部分，但没有量化到 WCAG 比值。**建议在一张亮壁纸和一张暗壁纸上各看一眼再定稿。**
2. **`DropShadowEffect` 的渲染开销没压测**：每个项目名一个投影，200 个项目时可能变慢。
   现有的 `perf` 只测布局切换，不覆盖"200 个带投影的项目"渲染。
3. **`tools/glass-causal.py` 目前不可靠**：换背景那一步的 z-order/前台锁控制不住，
   出现过"两次都变暗""抓到记事本"等情况，结论一律不可信。要么修好再引用，要么只看 `glass-proof.py`。
4. **设置窗口的截图没拍成**：本机当时开着系统「设置」应用并占据前台，窗口被压住，
   拍到的都是它。材质本身已用属性读回确认为 `BACKDROP=3`（见第二节表格），但**没有实拍图**。
5. **侧边栏新材质的边界情况只在本机验证**：贴边停靠、收起态（44 DIP）、
   多显示器切换只过了端到端里已有的用例，没在别的机器上试。
6. **非活动窗口会退成实心底色**：这是系统行为，但意味着"用 Alt+Tab 切走后截图"会得到实心效果，
   容易被误判成 bug。已在 `shoot-window.py` 里做了断言，人工复现时也要注意。
7. **没做动画**（按需求：进入/退出/滑入动画属于后续独立任务）。

## 七、如果要继续调

- 想更透：把 `BrushPanelGlass` 往下压（它现在承担"内容面板"这一层，20%）；
  再往下压文字会重新变糊，投影能补的空间有限。
- 想更沉：`BrushWindowBaseGlass` 往上加到 25% 左右，代价是壁纸只留得下颜色、留不下轮廓。
- 想验证改动是否真的生效：**不要看 XAML 里的数值**，跑 `tools/glass-proof.py reference` 看相关系数，
  或者 `tools/shoot-window.py` 出图后直接看空白区域有没有随壁纸起伏。
