# 阶段 9 · 手动补测清单（公开发布标准）

> 建立时间：2026-10-29
> 依据：`docs/competitive-landscape.md`（竞品调研）、`docs/stage8-plan.md` §6.4（8.4 遗留）
> 定位：项目已确定**公开发布、争取用户**，因此补测标准按"发给陌生人用、不能出事"来定，
> 而不是"自己能用就行"。
> 原则：**每个测试项必须有可判定的客观判据**，不写"感觉流畅"这类主观标准。

## 通用规则

1. 改缩放后**必须注销重登**（或重启），否则 DPI 不真正生效——这是 8.4 第一轮踩过的坑。
2. 每个场景都要**同时截图**：一张整屏（含任务栏，用来证明分辨率/缩放在屏内）、一张窗口局部。
3. 失败判据一律写进"已知限制"文档，**不得宣称已通过**。
4. 测试用的是 `publish/vm-package/` 里的自包含版（65,067,641 B，MD5 `7a26f62872789d2dd11bf20e0ec9758c`）。

## A 类：阻塞发布，必须全绿

### A1 - 8.4 剩余 DPI / 分辨率补拍（约 10 分钟）

| 缩放 | 待补场景 | 判据 |
|---|---|---|
| 100% | 全屏工作空间（分类视图） | 标题/搜索框/分类面板/项目卡片/移除拖放区/状态栏全部完整，无截断、无重叠、无溢出 |
| 100% | 悬浮窗 | 780×540 窗口完整在屏内，玻璃底色不穿帮，文字全不透明可读 |
| 100% | 设置窗口（滚到底） | 能看到「卸载前清理」与「诊断与排障」两个分区及「导出诊断包…」按钮 |
| 150% | 悬浮窗 | 同上 |
| 150% | 设置窗口 | 同上 |
| 150% | 全屏**自由分区**视图（顶栏「切换到自由分区」） | 画布、分区、未分区池区都可见且不被挤压成 0 高 |
| 125% | 全屏 / 悬浮窗 / 侧边栏收起态 各一张 | 同 100% 判据 |
| 1366×768 | 全屏 + 侧边栏 各一张 | 窗口不被挤变形，无控件重叠、无文字截断 |

另需补拍 `docs/stage8-84-evidence/84-batch1-00-unidentified.png`（当时只拍到壁纸）。

### A2 - 复核 175% 那条存疑记录（2 分钟）

上一轮 150% 那批的环境取证截图上，Windows「设置 › 系统 › 屏幕」的「缩放」读数是 **175%**，
与标注的 150% 不一致。

步骤：明确把缩放设成 **150%** → 注销重登 → 截一张设置页 → 再拍上面 A1 的 150% 三张。
判据：设置页「缩放」读数 = 150%，且与同批界面截图时间戳连续。

### A3 - 副屏停靠 / 混合 DPI（**目前完全空白，且是竞品主打项**）

步骤：
1. 接第二块屏，设成**主屏 100% + 副屏 125%**（或反过来，两种都试）
2. 切侧边栏模式 → 把侧边栏拖到副屏 → 看它停在**哪块屏**的边缘
3. 主屏、副屏各停靠一次（左/右都试）
4. 锁屏 → 唤醒
5. 拔掉副屏 → 等 10 秒 → 再插回
6. 改一次主屏分辨率，再改回来

判据（客观）：
- 侧边栏**始终贴在它所在那块屏**的边缘，不会跑到另一块屏，也不会半个身子出屏
- 拔插与改分辨率后，窗口仍完整可见（不为 NaN、不为屏外坐标）
- 混合 DPI 下文字不模糊、不被拉伸缩放

> 竞品参照：DeskBox 把"格子绑定到显示器硬件标识、每种连接组合独立布局"当作主打能力。
> 本项目这一项连数据都没有，是发布前最大的空白。

### A4 - 缺 .NET 运行时在**中文系统**上的报错文案（5 分钟）

背景：8.2 已有证据是英文系统上的英文报错框；中文系统的文案从未确认。

步骤：拿**便携版**（`publish/vm-package-portable/DeskSpace.exe`，527,965 B）在没有
.NET 10 桌面运行时的**中文** Windows 上双击。

判据：
- 弹出报错对话框（不静默失败）
- 文案是中文，且用户能看懂"需要安装 .NET 桌面运行时"
- 有可点击的下载入口

## B 类：竞品已覆盖、本项目无数据

### B5 - 长时驻留资源占用

竞品参照：DeskBox 公开称"全部格子打开时内存稳定在约 50 MB"，并做了 AOT 内存曲线测量。

步骤：开机自启后**静置 8 小时不操作**（中间锁屏一次），分别在 T0 / T+4h / T+8h 记录：
任务管理器里的**内存（专用工作集）**、**句柄数**、**线程数**、**GDI 对象数**。

判据：内存不持续增长（8 小时内增幅 < 20%，且无明显单调上升曲线）；句柄/线程/GDI 不单调增长。

### B6 - 大量项目时的性能

步骤：往桌面堆到 **200+ 个项目**（可用脚本批量造快捷方式，测完删掉），记录三项耗时：
① 冷启动到主窗口可见 ② 首次扫描完成 ③ 从分类视图切到自由分区视图。

判据：冷启动 < 3 秒；扫描 < 5 秒；切换无明显卡顿（< 1 秒）。
同时看 `logs/errors.log` 是否新增内容（应为 0 增长）。

### B7 - Windows 10 兼容性

背景：Mica 需要 Build ≥ 22621，Win10 会走**不透明回退**分支——代码写了但**从未实测**。

步骤：在 Win10（建议 19041 或 22H2）上装自包含版，跑一遍三种模式。

判据：
- 窗口**能正常显示**（不能白屏、黑屏、不显示，也不能只有边框没有内容）
- 悬浮窗/侧边栏（分层窗口）玻璃底色正常，不是全黑或全透明
- 托盘、快捷键、开机自启三项都能用

### B8 - 锁屏唤醒 / 远程桌面 / 睡眠恢复

这三个场景最容易让分层窗口（悬浮窗/侧边栏）跑到屏外或变透明。

每个场景后检查：窗口是否仍完整在屏内、能否正常呼出、`settings.json` 里的窗口坐标是否为有限值。
判据：三个场景下窗口均可见且可交互，配置里不出现 NaN / Infinity。

## C 类：核心卖点验证（"三形态共用一套数据"）

> C9 / C10 我会写成可执行脚本，见 `tests/` 下新增的验收程序，不需要手工点。
> 下面只列**必须人工肉眼确认**的补充项。

### C9 - 三模式来回切换的数据一致性（人工部分）

脚本会断言 JSON 层面的数据一致；人工需确认**视觉层面**也一致：

步骤：全屏模式建 3 个分类、拖 5 个项目进去、在自由分区里手动摆好位置并记录坐标 →
切悬浮窗 → 切侧边栏 → 再切回全屏。

判据：分类列表、项目归属、分区坐标、窗口位置偏好**全部保持**；三个模式下同一个项目的
图标与名称一致。

### C10 - 配置损坏后的真实恢复（人工部分）

脚本会断言"不崩 + 有备份"；人工需确认**提示是否友好**：

步骤：手动把 `settings.json` 改成非法 JSON → 启动应用。

判据：
- 应用不崩溃、不卡死
- 有用户能看懂的提示（不是英文异常堆栈）
- `%LocalAppData%\DeskSpace\backups\` 里留下了损坏前的原件
- 再用「导出诊断包」导一次，包里的 `manifest.txt` 能列出这份备份
