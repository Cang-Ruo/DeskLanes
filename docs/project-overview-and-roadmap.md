# DeskSpace 项目总览与后续建议

> 整理时间：2026-10-25（阶段 7 授权测试与安装/卸载脚本补齐之后）
> 代码规模：约 11,000 行 C#（Core 6,000 行 / App 3,000 行 / 测试 2,000 行）

---

## 一、项目定位与技术栈

Windows 11 本地桌面工作空间管理器：**不改变桌面文件的物理位置**，用虚拟分类 + 自由分区的方式
把桌面项目组织起来，并提供三种随叫随到的界面形态。

| 项目 | 内容 |
|---|---|
| 技术栈 | C# + WPF + .NET 10 LTS（`net10.0-windows`），MVVM（基类手写） |
| 第三方依赖 | **零**。全部 P/Invoke 自实现（热键、托盘、图标、快捷方式解析、已知文件夹） |
| 工程结构 | `DeskSpace.Core`（模型/服务/Win32 互操作）+ `DeskSpace.App`（WPF 界面/应用服务）+ 3 个测试工程 |
| 目标平台 | win-x64，单文件发布（framework-dependent） |
| 运行时依赖 | .NET 10 **桌面**运行时（`Microsoft.WindowsDesktop.App` 10.x） |

## 二、功能清单

### 1. 三种界面模式（共用同一份数据，切换不丢任何内容）

| 模式 | 说明 | 主要实现 |
|---|---|---|
| 悬浮窗 | 轻量快速启动窗口，全局快捷键呼出；支持搜索；可设失焦自动隐藏（Esc 也可隐藏） | `Views/FloatingWindow.xaml`、`FloatingWindowViewModel` |
| 全屏工作空间 | 1100×720 主窗口，含**分类导航式**与**自由分区式**两种布局 | `MainWindow.xaml`、`CategoryNavViewModel`、`FreePanelsViewModel` |
| 侧边栏 | 停靠屏幕左侧或右侧的快捷入口栏，可设宽度与失焦自动收起 | `Views/SidebarWindow.xaml`、`SidebarViewModel` |

模式切换入口：设置窗口单选、托盘菜单（悬浮窗/全屏/侧边栏）、`WindowModeManager`。

### 2. 桌面扫描与自动同步

- 扫描**用户桌面 + 公共桌面**（`SHGetKnownFolderPath`，不用会踩坑的逻辑桌面）
- 解析 `.lnk` 快捷方式目标（`ShortcutResolver`），提取多尺寸高清图标（`ShellIcons`，IShellItemImageFactory 256px）
- `FileSystemWatcher` 实时监听两个桌面 → 防抖（400ms / 3s）→ 后台重扫 → UI 线程合并
- 监听失败/目录不可访问时**降级为周期性重扫**，保证最终一致
- 可靠重命名迁移：只有系统明确给出"旧路径→新路径"才迁移关联，不靠文件名或时间猜测
- 失效判定**范围感知**：只对成功枚举的目录内项目判失效，避免"扫不到就被误删"

### 3. 组织能力（虚拟分类，只写 JSON，不改文件位置）

- 分类（分组）：创建、重命名、把项目指派到分类/取消分类
- 自由分区：创建面板、拖拽移动与缩放（ScaleTransform + TranslateTransform）、项目指派到分区、底部"未分区项目池"
- 自定义添加任意文件/文件夹为项目；移除项目
- 项目右键菜单（分类导航与自由分区两种视图都有）
- 全屏模式顶部搜索框实时过滤

### 4. 系统集成

| 功能 | 说明 | 默认 |
|---|---|---|
| 全局快捷键 | `RegisterHotKey` + 消息窗口，只支持组合键（默认 Ctrl+Alt+Space），不注册裸 Win 键、不使用键盘钩子；带"测试"与被占用提示 | 启用 |
| 系统托盘 | 自实现 `Shell_NotifyIcon`（图标、气泡、右键菜单）；菜单项：打开工作空间 / 三种模式 / 设置 / 退出 | 启用 |
| 开机自启 | HKCU Run 启动项，仅当前用户、免管理员 | **关闭**（opt-in） |
| 桌面图标隐藏 | 向 DefView 发 `WM_COMMAND 0x7402`（系统右键菜单同款），保存时再确认一次 | **关闭**（opt-in） |
| 关闭窗口最小化到托盘 | 否则直接退出 | 开启 |

### 5. 设置窗口

窗口模式选择 · 全局快捷键（可测）· 悬浮窗失焦隐藏 · 侧边栏停靠位置/宽度/失焦收起 ·
托盘最小化 · 开机自启 · 桌面图标隐藏 · **卸载前清理**（删自启项 + 恢复图标并同步配置）。

### 6. 配置、日志与安装

- 配置：`%LocalAppData%\DeskSpace\`（`settings.json`、`library.json`），带版本号与宽容加载/迁移
- 日志：同目录 `logs\`（同步日志）；单文件下用 `Environment.ProcessPath` 定位（避免 `Assembly.Location` 为空）
- 安装/卸载：`tools/install.ps1` / `tools/uninstall.ps1`，每用户、免管理员，已注册到「设置 → 应用 → 已安装的应用」

## 三、数据与存储

```
%LocalAppData%\DeskSpace\
  settings.json    窗口模式/布局/尺寸位置/快捷键/侧边栏/托盘/自启/图标 等
  library.json     项目 Items、分类 Groups、分区 Panels
  logs\            同步与诊断日志
```

数据模型带 `Origin`（用户桌面 / 公共桌面 / 自定义），分类与分区都是**虚拟**的——
`desktop.json` 里只记录"哪个项目属于哪个分类/分区"，磁盘上的文件一个字节都不动。

## 四、安全红线（设计约束，后续开发必须遵守）

1. 不移动、删除、修改桌面上的任何文件
2. 不随意写注册表：只写 HKCU 下三个点（Run 启动项、Uninstall 卸载项、HideIcons 由资源管理器写）
3. 不重启 Explorer（隐藏/恢复桌面图标用切换命令，不是重启）
4. 开机自启、桌面图标隐藏默认关闭，且需要用户逐次授权
5. 不用键盘钩子、不注册裸 Win 键

## 六、已知限制

1. 依赖目标机预装 .NET 10 桌面运行时；**缺运行时时的报错友好度未在干净环境验证过**
2. 无自动更新、无数字签名（可能触发 SmartScreen 提示）
3. 只在**一台机器**验证过（Win11 Build 26300、多显示器 + 虚拟显示器、DPI 1.25）；
   无第二台机器、无单显示器 / 标准 DPI / 不同缩放比验证
4. 开机自启**没有进入真实验收脚本**（`stage4-accept.ps1` 相关关键字出现数为 0），只有冒烟层断言
5. 托盘菜单项文本无法从外部读取（已知自动化限制）
6. 若第三方桌面工具接管桌面，可能找不到 DefView，此时桌面图标功能会如实报错（已有处理）

## 七、后续优化建议

### P1 —— 建议在做正式分发前完成

| # | 建议 | 理由 | 大致工作量 |
|---|---|---|---|
| 1 | **加一份自包含（SelfContained）发布配置** | 彻底消除"目标机没装 .NET 10 桌面运行时"这个最大的分发风险；体积约 70–90 MB，与现有 494 KB 版本并存供选 | 小（一个 pubxml + install 脚本选择来源） |
| 2 | **干净环境验证**：找第二台机器或虚拟机，分别验证"有 / 没有运行时"两种情况的报错，必要时在 exe 启动前补一层友好提示 | 当前唯一无法在本机替代的验证项 | 小（验证）+ 中（友好提示） |
| 3 | **多显示器 / DPI 矩阵验证**：单显示器、100% / 150% / 200% 缩放下检查侧边栏停靠与悬浮窗定位 | 目前只验证过 DPI 1.25 的多显示器环境 | 中（验证 + 可能修定位逻辑） |
| 4 | **把开机自启纳入真实验收脚本** | 它是唯一没有端到端系统级验证的功能（现在只有注册表层断言） | 小 |

### P2 —— 功能与体验

| # | 建议 | 理由 |
|---|---|---|
| 5 | **配置导出 / 导入**（把 settings.json + library.json 打包成一个文件） | 换机、重装时最实用；也和卸载脚本"默认保留配置"形成闭环 |
| 6 | **自动更新检查**（读静态 JSON / GitHub Release，发现新版本提示下载，不做静默自更新） | 无更新机制是目前手工换 exe 的主要痛点；保持"不静默改本机文件"的安全约定 |
| 7 | **搜索增强**：拼音首字母匹配、最近使用排序、键盘上下选择 + 回车打开 | 悬浮窗是高频入口，搜索效率直接决定体验 |
| 8 | **项目右键菜单补全**：打开文件所在位置、以管理员运行、重命名/改分类 | 目前项目菜单项较少 |
| 9 | **分类与分区的自定义排序**（拖拽排序 + 手动顺序持久化） | 组织类功能的自然延伸 |
| 10 | **图标缓存与内存**：大桌面下的图标缓存上限 + 手动清理入口 | `IconService` 已有缓存，缺上限与清理 |

### P3 —— 工程与质量

| # | 建议 | 理由 |
|---|---|---|
| 11 | **把 1944 行的 SmokeTests 控制台程序拆成 xUnit 工程并接入 CI** | 现在是单一大文件，回归定位与并行执行都不方便 |
| 12 | **全局未捕获异常兜底**：写 `errors.log` + 友好提示，而不是崩溃退出 | 发布版的必备兜底 |
| 13 | **日志轮转与"导出诊断包"**（一键打包配置 + 日志） | 用户报故障时最省事 |
| 14 | **配置版本迁移的回归测试**：为每个 `DataVersions` 升级路径各加一条用例 | 版本迁移出错会直接毁掉用户的分类数据 |
| 15 | **国际化**：把界面硬编码中文抽到资源文件（至少预留结构） | 若要外部分发，英文界面是常见需求 |

### 不建议做（至少现在）

- **改成 MSI / 安装向导**：现有 PowerShell 脚本已覆盖安装、快捷方式、卸载登记，且可读可审计；引入 WiX/Inno 会破坏"零第三方依赖"的约定
- **静默自动更新 / 后台常驻服务**：与"不动桌面、不替用户做决定"的安全约定冲突
- **启用 ReadyToRun 或裁剪**：体积与启动速度的收益不抵反射/COM 互操作的裁剪风险
