# 24 小时长时驻留实测报告

> 结论：**没有泄漏**。私有内存前几小时预热后走平并回落，句柄 / GDI / USER / 线程
> 在最后 1 小时全部持平或下降，`errors.log` 全程零增长。
> 原始数据：`soak-24h.csv`（288 个采样点，每 5 分钟一次）。

## 一、怎么测的

`tools/soak-8h.py --hours 24 --interval-min 5`，启动真实的自包含 exe
（`publish/win-x64-selfcontained/DeskLanes.exe`），每 5 分钟直接读进程计数器：
私有内存 / 工作集 / 句柄 / GDI / USER / 线程 / `errors.log` 大小。

- 起止：`2026-11-09 01:50:44` → `2026-11-10 01:45:44`（最后一个采样点）
- 覆盖时长 **23.92 小时**，288 个采样点
- 采样期间发生过的事件：真实物理热插拔（拔/插左侧竖屏）、三次运行中改分辨率、
  多次回归工具启动与关闭实例。曲线里的起伏包含这些事件，不是纯净空闲态。

## 二、结果

| 指标 | 起始 | 峰值 | 结束 | 最后 1 小时 |
|---|---:|---:|---:|---|
| 私有内存 | 294.6 MB | 532.2 MB | **229.5 MB** | 242.6 → 229.5（−13.1） |
| 工作集 | 374.0 MB | 556.2 MB | 117.8 MB | 130.6 → 117.8（系统回收页） |
| 句柄 | 761 | 1035 | 879 | 885 → 879（−6） |
| GDI 对象 | 49 | 98 | 85 | 85 → 85（持平） |
| USER 对象 | 40 | 55 | 52 | 52 → 52（持平） |
| 线程 | 73 | 98 | 67 | 67 → 67（持平） |
| `errors.log` | 3634 B | — | 3634 B | **零增长** |

**私有内存 294 → 532 → 229 MB 不是泄漏。** 前几小时是预热（图标缓存、首次扫描、
WPF 资源加载），之后没有单调上升；最后 1 小时反而下降 13 MB，工作集被系统回收到
117.8 MB。句柄/GDI/USER/线程都在预热后进入平台，最后 1 小时没有一项增长。

这与阶段 9.8 的 6 小时结论（最后 2 小时 +3.9 MB、最后 1 小时 −1.0 MB）一致，
只是把观察窗口拉长到近 24 小时，结论不变。

## 三、口径与限制

- 私有内存用 `GetProcessMemoryInfo → PrivateUsage`，比工作集可信（工作集会被系统回收）。
- 采样期间有真实热插拔与改分辨率事件，因此不能把曲线当成"纯空闲"基线；
  但这些事件都没有造成指标持续抬升，反而更接近真实使用。
- 仍未覆盖：真实睡眠 / 休眠唤醒后的恢复、远程桌面会话。
- 这次跑的是**阶段 14 之前的构建**（01:50 启动）。阶段 14 改的是扫描合并语义与
  界面交互，不涉及长驻的资源持有；但严格说，新构建的 24h+ 驻留没有重新跑过。
